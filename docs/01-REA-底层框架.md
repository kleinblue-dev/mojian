# 01 · REA：拆开一个在线心理学实验的底层框架

> **对象**：<https://youth-fertility-study-gduf-web.onrender.com/> —— 广东金融学院应用心理学专业团队「青年生育意愿研究」在线实验
> **方法**：REA（Reverse Engineering Analysis）= **R**econ 侦察 → **E**xtract 提取 → **A**bstract 抽象
> **证据基线**：全部结论来自**本地离线资产**（`assets/` 下三个文件），未向线上 POST 任何数据（避免污染真实科研数据），仅做只读 GET。
> **配套细目**：[`analysis/01-state-machine.md`](analysis/01-state-machine.md)（状态机）·[`analysis/02-data-model.md`](analysis/02-data-model.md)（字段字典）·[`analysis/03-api-contract.md`](analysis/03-api-contract.md)（接口契约）·[`analysis/04-abstract-framework.md`](analysis/04-abstract-framework.md)（抽象层）·[`analysis/05-findings.csv`](analysis/05-findings.csv)（发现清单）

---

## 0. 摘要：这个站到底是什么

**一句话**：它不是"问卷网站"，是一台**浏览器内的单次随机对照微观试验装置**——用 AI 的"谄媚（sycophancy）"作为干预变量，测量它是否会**固化**青年的生育态度。

九个关键事实：

1. **技术栈**：Vite + React 18 单页应用（`createRoot` + `StrictMode`），单个 JS bundle 260,884 B，单个 CSS 212,312 B（Tailwind v4 语义 token + `oklch()` 色板 + shadcn 风格 Card），部署在 **Render**（`x-render-origin-server`），前置 **Cloudflare**。
2. **协议**：入口选组（A/B）→ **10 步线性状态机**（知情同意 / 前测 / 基本信息 / 开放性量表 / AI 对话 / 后测 / 用户体验 / AI 信任 / 研究说明 / 完成）。
3. **干预**：**6 轮硬上限**的 LLM 对话，模型为**火山方舟 · 豆包 Seed 2.1 Pro**；每轮把**全量历史**重发；非流式。
4. **测量**：前测 8 题（7 点）全部在后测 16 题中原 wording 重复（8 题复测 + 8 题新增 AI 感知/争论信心）；BFI 开放性 10 题（5 点，反向按**数组下标**）；UX 4 题；AI 信任 8 题（5 点）。
5. **数据**：单次 `POST /api/submit` 提交全量扁平 JSON（54 个答案 key，值全为字符串）+ 客户端 CSV/TXT 备份；**零本地持久化**。
6. **服务端只有 3 个端点**：`/api/assign`、`/api/chat`、`/api/submit`；GET 一律 405；其余路径被 SPA fallback 成 index.html。
7. **补丁层**：`experiment-patch.js` 是一个 **MutationObserver 驱动的 DOM 覆盖层**，可以在不重新构建前端的前提下改写文案、注入提示、**替用户作答并推进状态机**（已内含 10 道心算题的答案数组）。
8. **真实研究目的藏在最后一步的 debrief 里**：AI 的肯定/附和/合理化 → 立场确认感 → 生育态度的进一步固化。
9. **它的最大价值不是界面，而是"干预与验证在同一页面内闭环"**——这正是绝大多数"疗愈/心理健康"产品缺失的东西。

## 1. REA 方法：三步与三条纪律

| 步 | 做什么 | 本项目的具体动作 |
|---|---|---|
| **R**econ | 只观察，不打扰 | 拉取 HTML/JS/CSS；读响应头判断部署与 CDN；用 UA 变换、OPTIONS、未知路径探测框架与路由；**全程只读** |
| **E**xtract | 从产物反推设计 | 从压缩 bundle 提取中文文案（237 条模板字符串）、状态变量、守卫逻辑、API 调用点、计分公式、debrief 原文 |
| **A**bstract | 剥离题材，还原骨架 | 把"生育实验"抽象成 6 层通用框架，标出每个层的**可替换边界**与**换题材时最小重写集** |

三条纪律（决定这份报告可信度）：

1. **事实与推断分离**：凡不能在前端证伪的（服务端提示词、分组机制、存储后端），一律标注【推断】，不写成结论。
2. **不发写请求**：这是**真实在跑的科研实验**。一次 `POST /api/assign` 就会往研究者的数据集里插入一条假被试。REA 的边界感本身就是专业性的体现。
3. **可复现**：每条结论都给出字符偏移或文件行号，任何人可用 `node -e "…slice(a,b)"` 复核。

## 2. Recon：外部侦察记录

| 观察项 | 结果 | 推断 |
|---|---|---|
| `x-render-origin-server: Render` / `cf-ray` / `server: cloudflare` | Render 托管 + Cloudflare 前置 | 免费/低价档，单区域 |
| `index.html` 仅 3 个资源：一个 JS、一个 CSS、一个 patch 脚本 | 标准 Vite 生产产物 | 无 SSR、无路由库 |
| 未命中路径（`/robots.txt`、`/api/health`）返回 **200 + index.html** | SPA history fallback 写在服务端 | 后端是一个极简 Node 服务，除 3 个 POST 外只做静态托管 |
| `GET /api/assign|chat|submit` → **405**；`OPTIONS` → **405** | 三个端点均只接受 POST，且未实现 CORS 预检 | 典型 Express `app.post(...)`，无 `cors()` 中间件 |
| iPhone / Desktop / Googlebot 三种 UA 拿到**同一个 bundle hash**（`index-pynnv8l5.js?v=20261009-phone`） | 无 UA 分流 | 版本号虽标 `phone`，实际统一 |
| `<meta name="description">` = "广东金融学院应用心理学专业团队在线实验" | 学术项目，非商业产品 | 数据用途为研究 |
| 全程无第三方统计/埋点脚本 | 有意为之 | 隐私与伦理合规考虑 |

**侦察阶段最有价值的一条**：`experiment-patch.js` 独立于 bundle 加载，说明**线上协议曾被"热补丁"修改过**——这是判断"这套框架是否可运营"的关键线索（见 §5.3）。

## 3. Extract：这套实验的设计还原

### 3.1 研究目的（来自最后一步的 debrief 原文）

> 本研究以生成式人工智能（AI）的"谄媚"现象为切入点，关注 AI 在青年婚姻与生育咨询过程中对个体婚育观念的影响。AI 在提供信息和情绪支持时，也可能通过**肯定、附和和合理化**用户已有观点，使人产生"自己的想法是正确的""自己的选择是合理的"等立场确认感。本研究通过**比较互动前后的测量**，考察这种回应是否会使原有生育态度得到进一步确认和稳定。

### 3.2 实验设计矩阵（还原）

| 要素 | 还原结果 | 证据 |
|---|---|---|
| 设计类型 | 两组前后测（2 × pre/post），组间为 AI 回应风格 | 入口 A/B + 同一套前后测 |
| 自变量 | AI 的"附和程度"（A 组 vs B 组） | 入口门 + 服务端 `conditionCode` |
| 因变量（主） | 生育立场的**确定性/合理性/可辩护性**（前后测同题差值） | `pre_certainty`…`pre_explain` ↔ `post_reason_count`…`post_explain` |
| 因变量（次） | 对 AI 的感知（`post_ai_agree/support/perspective/firmer`）、争论信心 | 后测第 1–4、13–16 题 |
| 中介/调节 | AI 信任（TAI 8 题）、用户体验（UX 4 题）、**开放性人格（BFI-O 10 题）** | 独立三步量表 |
| 干预剂量 | 6 轮对话（硬上限，双门禁） | `turns >= 6` 才放行 |
| 干扰/清洗 | 心算任务（当前 bundle 已移除，补丁保留其逻辑） | `experiment-patch.js` `skipMathPage` |
| 被试报酬 | 支付宝手机号（用于被试费） | 基本信息步 |

**判读**：这是一个设计得相当"正"的心理学实验——有前后测同构、有中介变量、有 debrief、有报酬、有匿名声明。它的学术性不是问题，问题在工程实现（见 §5）。

### 3.3 干预层的三个精巧设计（值得抄）

1. **立场注入首轮**：客户端把前测立场转成一句自然语言（`我倾向于生孩子 / 我倾向于不生孩子 / 我还没想好要不要孩子`），连同 `stanceScore`（原始 1–7 分）、`participantId`、全量消息一起发给 `/api/chat`。这让服务端**不需要知道量表结构**就能做个体化调制——接口极简，语义完整。
2. **条件码由服务端回传，客户端不解释**：被试只看到"进入 A 组 / B 组"这个无信息量的标签，**不知道 A/B 各代表什么**；`conditionCode` 只在 `/api/chat` 响应里出现，被静默存下（`h(r.conditionCode)`）后原样进 payload。客户端**没有任何"条件码 → 行为"的映射**——说明条件只影响服务端怎么回话，不影响前端流程。这是**接近零成本的单盲**实现（严格说被试知道自己是"某组"，只是不知道组含义）。
3. **双门禁的回合上限 + 降级**：`turns>=6` 时既禁用输入框、又在发送函数里二次拦截；网络失败时不是报错，而是返回一句**设计过的兜底话术**并标记 `source:'fallback'`。这让实验在被试侧永远"看起来正常"——对研究是优点，对产品是**必须改掉的缺点**（掩盖故障）。

### 3.4 测量体系（54 个答案 key）

| 组 | 题数 | 点数 | 关键实现细节 |
|---|---|---|---|
| 前测 `Un` | 8 | 7 | 中段锚点写死"不确定"；`pre_intention` 是唯一立场锚题，被复用三处 |
| 后测 `Wn` | 16 | 7 | 锚点按 id 子串**动态拼**（`includes('hesitation')`…），不是常量 |
| 开放性 `Gn` | 10 | 5 | 反向题按**数组下标** `t===6 || t===8`，题库一重排就静默算错 |
| 体验 `Kn` | 4 | 5 | `ux_enjoyment_mean` **只取了前 2 题**，后 2 题（再交互意愿、回复质量）未进入指标 |
| 信任 `qn` | 8 | 5 | 反向按 `t===5`；取均值 |
| 人口学 | 7 | — | 年龄/性别/兄弟姐妹/感情状态/手机尾号/支付宝/户籍地 |

### 3.5 数据与部署

- **提交**：`POST /api/submit`，body = 元信息（`participant_id / condition_code / started_at / finished_at / duration_seconds`）+ `...answers` 平铺 + 3 个派生指标 + `chat_turns / chat_attempts / chat_transcript`。
- **备份**：完成页可下载 CSV（KV 竖表，带 BOM/CRLF）与 TXT（对话记录）——**这是唯一的数据冗余**。
- **持久化**：无。刷新页面 = 进度全丢，且因为只在最后一步提交，**中途退出 = 数据不存在**。
- **参与者 ID**：客户端生成，`GDUF-YYMMDD-<group><随机字母><000–999>`。可伪造、可碰撞，服务端无校验证据。

## 4. Abstract：六层框架（与题材无关）

完整定义见 [`analysis/04-abstract-framework.md`](analysis/04-abstract-framework.md)，这里只给骨架：

```
L1 呈现层   —— 外壳/进度条/问题卡/对话面板/完成页       （换 CSS token 即可换皮）
L2 协议层   —— step 索引 + answers + messages + 守卫表   （纯数据表，骨架复用）
L3 测量层   —— 题库 + 点数 + 锚点 + 反向 + 计分公式      （全换）
L4 干预层   —— 立场派生 + 首轮模板 + 回合策略 + 兜底      （话术全换）
L5 数据层   —— payload 组装 + 提交 + 导出 + 持久化策略    （字段名是数据）
L6 补丁层   —— MutationObserver 声明式规则，旁挂 L1      （引擎复用，规则全换）
```

**层间不变式（移植时必须守住）**：单一状态源 / 守卫在转移处执行 / step 单调递增 / 提交幂等 / 反向题声明化 / 网络调用带超时 / 提交前本地草稿 / **PII 与测量数据分离** / 补丁层只读 DOM / 文案集中管理 / 字段顺序确定 / **schema_version**。

其中后 6 条原实现**都没做到**——这既是缺陷，也是移植时的检查清单。

---

## 5. 关键发现（15 条）

### 5.1 设计层面（值得学）

1. **干预与测量同页闭环**：这是它最稀缺的资产。绝大多数疗愈产品只做干预。
2. **单盲零成本实现**：条件码只出现在服务端响应里，客户端不持有。
3. **接口语义极简**：三个端点、无 ORM、无会话，LLM 调用只需 `stance + stanceScore + messages`。
4. **LLM 输出全部 transcript 化**：干预过程本身成为可分析数据。
5. **debrief 规范**：结束前如实告知真实目的，并提醒不要向他人泄露假设。

### 5.2 工程层面（移植前必须修）

6. **零持久化**：中途退出数据全丢（`_e` 只由 `ye()` 调用）。
7. **提交无幂等、无重试、无超时**：弱网即丢；重复走流程产生重复记录。
8. **知情同意无记录**：step 0 没有任何字段，伦理审计上无法证明同意。
9. **反向题按下标**：`t===6/t===8/t===5`，改题库即静默错位。
10. **派生指标与采集不一致，且有两个"假指标"**：UX 4 题只算 2 题进均值；`chat_turns ≡ chat_attempts`（因为 `onTopic` 恒为 `true`，两个指标实际是同一个数）；`pe()` 的第二个参数（轮次）被同名局部变量遮蔽，**轮次从未发往服务端**——服务端只能靠 `messages.length` 反推。
11. **PII 与科研数据同表**：户籍地、支付宝手机号与态度数据一起提交。
12. **按钮文案与实际行为不符**：step 7 写"提交全部问卷"，实际不提交；真正的提交在 step 8。
13. **失败一律降级为"AI 网络不稳定"**：掩盖 4xx/5xx/超时，污染数据质量判断。
14. **无 schema_version**：协议迭代后历史数据不可比。

### 5.3 协议层面（最值得写进方法论的发现）

15. **线上协议被 DOM 补丁"热改"过，而且补丁已经部分失效**：
    - 补丁脚本里 `MATH_ANSWERS`（10 道心算题答案）、"11 步→10 步"的进度归并、`math_*` 行过滤，都指向一个**含心算干扰任务的 11 步版本**；
    - 但当前 bundle 的步骤表长度是 **10**，全 bundle **没有任何"心算"字符串**——说明心算页已在某次构建中被移除，补丁里 4 类规则有 3 类成了**死代码**；
    - 同时，补丁要改的文案（"问卷和一次 AI 对话"）**已经出现在 bundle 里**，说明补丁的修改曾被烘焙进构建产物。
    - **含义**：线上数据很可能**混合了不同协议版本的被试**，而系统里没有任何协议版本字段。对一个科研项目，这是比 UI bug 严重得多的问题；对我们要做的产品，这是**必须内建 `schema_version` 与规则指纹**的直接教训。

## 6. 判据：这套框架值不值得移植？

用一个三问判据：

| 问题 | 回答 |
|---|---|
| **它稀缺吗？** | 稀缺的不是技术，是**"敢在自己身上做对照"的产品观**。技术上它很朴素（10 步问卷 + 1 个聊天框）。 |
| **它可迁移吗？** | 可迁移度 **80%**：6 层里 L1/L2/L5/L6 几乎原样复用，只有 L3（题库）与 L4（干预话术）需重写。 |
| **它迁移后还成立吗？** | 成立，但**必须换一个问题**：原站问"AI 会不会让人更固执"，水墨版要问"墨会不会让人松一点"。同一台仪器，反向使用。 |

**反直觉结论**：这个站真正能变现的形态，可能不是"抄一个疗愈 App"，而是**把框架本身做成产品**——一个给心理学/公卫/教育研究者用的"在线干预实验基础设施"。因为它的客户（高校心理系）已经在用 DOM 补丁手工改协议了，这是需求存在的铁证。详见 [02-水墨疗愈-移植方案.md](02-水墨疗愈-移植方案.md) §8。

## 7. 结论

1. **底层框架 = 线性协议状态机 + 量表引擎 + LLM 有限轮干预 + 同构前后测 + 一次性数据回收 + DOM 补丁层**，六层之间耦合极低。
2. **它的学术设计是合格的，工程实现是脆弱的**：无持久化、无幂等、无版本、PII 混表、协议被热补丁改到不可追溯。
3. **对"水墨疗愈"的移植价值，不在视觉、不在 AI 对话，而在"干预-测量闭环"这一结构本身**——这正是疗愈品类最缺的东西。
4. **移植的第一条工程纪律**：先补上 `schema_version` + 本地草稿 + 幂等提交 + PII 分离，再谈题材。
5. **移植的第一条产品纪律**：把主结局从"态度固化"换成"状态松动"，并**预注册 + 主动对照**，否则会重演本领域"大效应量、低质量证据"的老路。
